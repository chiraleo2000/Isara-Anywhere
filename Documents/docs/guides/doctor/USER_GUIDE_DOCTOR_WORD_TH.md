## บทนำ

คู่มือฉบับนี้จัดทำตาม**มาตรฐานการรายงานภาษาไทย** สำหรับพอร์ทัลแพทย์และผู้ดูแลระบบ (URL เดียวกัน แยกสิทธิ์ JWT):

| ประเภทเอกสาร | แบบอักษร | ขนาด |
|---|---|---|
| รายงาน / คู่มือ Word | **TH Sarabun New** | เนื้อหา **16 pt**, ระยะบรรทัด **1.15** |
| สไลด์นำเสนอ | **FC Iconic** | หัวข้อ **32 pt**, เนื้อหา **18 pt** |

แพทย์ = **HOST** ของการประชุม (Lobby, Admit, บันทึก, สรุป AI) — ผู้ดูแล = จัดสรร Pool และอนุมัติบัญชี

**ขอบเขตกระบวนการ (อ้างอิง Processes/):**
- ภาพรวมพอร์ทัล (`Processes/Pages/Doctor-Portal/00_Doctor_Portal_Overview.md`)
- GATE0: ผู้ป่วยจอง → Pool → แอดมินจัดสรร → แพทย์ยืนยัน → Health Meeting
- วิดีโอคอล, Guest link, บันทึก, EMR (`Processes/VIDEO_MEETING_JITSI_GEMINI.md`)

**Doctor & Admin Portal** ใช้ URL เดียวกัน แต่แสดงเมนูตามบทบาท:

| บทบาท | ขอบเขต | หน้าที่หลัก |
|---|---|---|
| **แพทย์ (Doctor)** | ผู้ป่วยของตนเอง | คิว, Health Meeting, EMR, วิดีโอคอล, เนื้อหา |
| **ผู้ดูแล (Admin)** | ทั้งองค์กร | จัดสรรแพทย์, Pool, อนุมัติบัญชี/เนื้อหา |

### เอกสารกระบวนการที่เกี่ยวข้อง

- `Processes/Pages/Doctor-Portal/00_Doctor_Portal_Overview.md` — เส้นทางและเมนู
- `Processes/Appointment_Workflows.md` — Pool, จัดสรร, ยืนยันนัด
- `Processes/VIDEO_MEETING_JITSI_GEMINI.md` — Lobby, HOST, Guest


## A0. การเข้าสู่ระบบ

**วัตถุประสงค์ของหมวดนี้:**

แพทย์และผู้ดูแลใช้พอร์ทัลเดียวกัน แยกสิทธิ์ด้วย JWT role

**ลำดับกระบวนการในระบบ (สรุป):**

- เปิด URL พอร์ทัลแพทย์ (Cloud dev-testing หรือ localhost:8080)
- แพทย์ใหม่: สมัคร → รอ Admin อนุมัติ → ล็อกอินได้
- Admin: ล็อกอินด้วยบัญชี admin — เห็นเมนู Pool และอนุมัติ
- Google SSO: ใช้อีเมลที่ลงทะเบียนแล้ว
- ตรวจ redirect ไป `/doctor/:id/dashboard`

**ข้อควรระวัง:**

- แพทย์ที่ยัง pending จะไม่เห็นเมนูคลินิกเต็มรูปแบบ

**อ้างอิง:** `Processes/Pages/Doctor-Portal/01_Login_Page.md`

### 1. หน้าเข้าสู่ระบบแพทย์/ผู้ดูแล

**วัตถุประสงค์ของขั้นตอน:**

บัญชีแพทย์ต้องได้รับอนุมัติก่อน

**ขั้นตอนการใช้งาน (ละเอียด):**

1. เปิด URL พอร์ทัลแพทย์
   - **ปฏิบัติ:** ดำเนินการตาม UI จนจบขั้นนี้ — อย่าข้าม modal ยืนยัน
   - **ตรวจบนหน้าจอ:** ฟอร์มล็อกอิน Doctor Portal
   - **บทบาท:** แพทย์/ผู้ดูแล
   - **รายละเอียด:** ขั้นที่ 1 ต้องสำเร็จก่อนขั้นถัดไป; บันทึก appointmentId/meetingId จาก Network หากต้องส่งต่อ IT
   - **ตรวจสอบ:** HTTP 2xx บน API หลัก; ไม่มี toast error
2. กรอกบัญชีที่ผู้ดูแลสร้างให้
   - **ปฏิบัติ:** ดำเนินการตาม UI จนจบขั้นนี้ — อย่าข้าม modal ยืนยัน
   - **ตรวจบนหน้าจอ:** ฟอร์มล็อกอิน Doctor Portal
   - **บทบาท:** แพทย์/ผู้ดูแล
   - **รายละเอียด:** ขั้นที่ 2 ต้องสำเร็จก่อนขั้นถัดไป; บันทึก appointmentId/meetingId จาก Network หากต้องส่งต่อ IT
   - **ตรวจสอบ:** HTTP 2xx บน API หลัก; ไม่มี toast error

**ข้อควรปฏิบัติในขั้นนี้:**

- แพทย์ที่ยัง pending จะไม่เห็นเมนูคลินิกเต็มรูปแบบ
- อ้างอิงกระบวนการ: `Processes/Pages/Doctor-Portal/01_Login_Page.md`

**ผลลัพธ์ที่คาดหวัง:**

- ฟอร์มล็อกอิน Doctor Portal
- ดำเนินการต่อได้โดยไม่มีข้อผิดพลาด (HTTP 4xx/5xx) บนฟังก์ชันหลัก
