# Meeting Room — Jitsi Video Session

> **Canonical meeting spec (v1.7.53).** This is the single real Jitsi flow. The legacy
> `VirtualMeeting.tsx` page and `/virtual-meeting/:id` route are **removed**; doctors and patients
> join the embedded Jitsi room only via the in-app route `/(doctor|)/meeting/:appointmentId`
> (components `MeetingRoom.tsx` for the doctor host and `PatientMeetingRoom.tsx` for the patient).
> No external `meet.jit.si` browser tabs. Doctor is host (Izara lobby `host-present` +
> `lobby/admit-all`); patient video mounts only after `waitForHostReady`.

**Component:** `MeetingRoom.tsx` (doctor host) / `PatientMeetingRoom.tsx` (patient) / `JitsiMeetingShell.tsx`
**Route:** Doctor `/doctor/:userId/meeting/:appointmentId` · Patient `/meeting/:appointmentId`
**Port:** Meeting server `localhost:3020`
**Thai Title:** ห้องประชุมออนไลน์

## Purpose

Hosts the live Jitsi consultation with lobby admit, host-ready gate, and `data-testid="jitsi-meeting-container"`.

### วัตถุประสงค์

- **รายงาน / Word:** แบบอักษร **TH Sarabun New** ขนาดเนื้อหา **16 pt** ระยะบรรทัด **1.15** (มาตรฐานรายงานภาษาไทย)

- สร้างไฟล์จริง: `python scripts/build-portal-user-guides.py` → `docs/guides/patient|doctor/USER_GUIDE_*_WORD_TH.docx` และ `*_PPT_TH.pptx`

### ขอบเขตและบทบาท

Meeting Server รับ lobby, บันทึก, transcription, post-meeting pipeline (`postMeetingPipeline.js`)
Production ใช้ `meet.jit.si` — บันทึกจากเบราว์เซอร์แพทย์ ไม่ใช่ Jibri

### ลำดับความสัมพันธ์กับ workflow อื่น

1. **นัดหมาย** — สถานะ `confirmed` ก่อนเปิดวิดีโอ (`Processes/Appointment_Workflows.md`)
2. **ประชุม** — Izara Lobby → Jitsi → บันทึก → สรุป AI (`Processes/VIDEO_MEETING_JITSI_GEMINI.md`)
3. **บันทึกทางการแพทย์** — EMR / สั่งยา / แล็บ หลังแพทย์ตรวจสอบ AI
